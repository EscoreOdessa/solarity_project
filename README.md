# EScore Energy — оновлення цін СЕС

Скрипт оновлює ціни у вкладці **«Довідник обладнання та цін»** робочої Google-таблиці
(шаблон кошторису) з прайсів постачальників і зберігає прайси, довідник і зіставлення
в базі **PostgreSQL (Supabase)**.

Сайт кошторису (`smeta`) і шаблон не змінюються: вони, як і раніше, читають ціни з «Довідника».

---

## Схема

```
прайси в папці Google Drive
        │  price_finder.py (парсер для кожного постачальника)
        ▼
PostgreSQL (Supabase, схема escore) ── ціни рахує база: прайс + escore.pricing_rules
        │
        ▼
«Довідник обладнання та цін» у шаблоні ──► smeta (без змін)
```

| Система | Роль |
|---------|------|
| Сайт `smeta` | підготовка кошторису |
| Google Sheets | проєктні кошториси, «Довідник» як інтерфейс |
| PostgreSQL | прайси, історія цін, довідник, зіставлення, правила цін |
| 1С / Perfectum | облік, закупівлі, проєкти (обмін налаштовує сторонній розробник) |

---

## Що робить один запуск

1. Бере в папці з прайсами найсвіжіший файл кожного постачальника: **ETI, CHINT, БДК (DKC), Kablex, KOPOS**
   (визначається за назвою файлу; найсвіжіший — за **датою в назві**, а не за датою зміни файлу на Диску).
2. Розбирає кожен прайс своїм парсером в однаковий вигляд: артикул, назва, група, ціна, валюта.
3. **База:** записує прайс (`supplier_items`, `price_snapshots`), якщо файл із такою назвою
   ще не завантажувався (`⏭ вже завантажено` у лозі). Нова дата в назві файлу = новий прайс.
4. Зіставляє позиції «Довідника» з прайсами: колонка J → артикул у колонці E → артикул у назві → точний збіг назви.
5. **База:** перезаписує довідник і прив'язки (`reference_items`, `item_mappings`).
6. Пише в «Довідник» ціну, **яку порахувала база**, постачальника, артикул і джерело (колонка K).
7. Звіряє ціни база ↔ таблиця (`🟰` — розбіжностей немає).
8. Оновлює вкладку «На перевірку» і підсвітку.

Запуск: щопонеділка (фактично раз на 2 тижні) або вручну —
**Actions → Оновлення цін СЕС → Run workflow**.

## Як працювати з «Довідником»

| Що потрібно | Що зробити |
|-------------|-----------|
| Прив'язати позицію до прайсу | колонка J: `Kablex: MBN232`, `БДК: 35264`, `ETI: 2163518`, `CHINT: 131361`, `KOPOS: KU 68-45_KA` |
| Позиція свідомо без прайсу | колонка J: `-` — ціна лишається ручною, у «На перевірку» не потрапляє |
| Ціна вручну | колонка D у рядку без прив'язки; у базі — `manual_price`, джерело `manual` |
| Прийняти різку зміну ціни (>50%) | очистити стару ціну в колонці D |
| Новий прайс | покласти файл у папку; назва починається з постачальника і містить дату: `eti_2026_11_01.xlsx` |

## Знижки і ПДВ

Знижки зберігаються в базі, таблиця **`escore.pricing_rules`** (Supabase → Table Editor → схема `escore`).
Змінили знижку там — наступний запуск поставить нові ціни в «Довідник».
Якщо код і база рахують по-різному, у лозі з'явиться `ℹ Код і база рахують ціну по-різному`.

| Постачальник | Правило |
|--------------|---------|
| ETI | −25% від ціни в грн з ПДВ |
| CHINT | знижка вже в прайсі |
| БДК (DKC) | рекомендована ціна без ПДВ × 1.2 |
| KOPOS (Ресурс Електро) | ціна без ПДВ за 1000 шт/м ÷ 1000 × курс EUR з файлу −15% × 1.2; українські версії артикулів — з суфіксом `_UA` |
| Kablex | за групою: кабель −37%, Hager −30%, Schneider / Kopos / ZUBR −25%; EUR/USD за курсом НБУ |

## База даних

Схема — `db/schema.sql`, початкові дані — `db/seed.sql`.

| Таблиця / подання | Що в ній |
|-------------------|----------|
| `v_current_prices` | усі позиції прайсів з поточною ціною в грн |
| `v_reference_prices` | ціна кожної позиції «Довідника» і її джерело (`price_list` / `manual` / `none`) |
| `v_review` | черга «На перевірку» |
| `import_runs` | журнал завантажених файлів прайсів |
| `reference_items.code_1c` | поле для коду номенклатури 1С (заповнюється при налаштуванні обміну) |

**Повернутися до розрахунку цін у коді** (якщо з базою щось не так):
Settings → Secrets and variables → Actions → вкладка **Variables** → `PRICE_SOURCE` = `code`.
Якщо база недоступна, скрипт сам переходить на розрахунок у коді й оновлює таблицю як раніше.

## Секрети (Settings → Secrets and variables → Actions)

| Секрет | Що це |
|--------|-------|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | ключ сервісного акаунта Google (таблиця + Диск) |
| `SHEET_URL` | посилання на робочу таблицю |
| `DATABASE_URL` | рядок підключення Supabase (Session pooler) |
